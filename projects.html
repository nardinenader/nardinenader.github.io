01Overview

Fleura is a real-time graphics engine I built from scratch in C++ on top of the Vulkan API. Working at the Vulkan level meant owning the parts that higher-level engines hide: direct control of GPU resources and memory, and the pipeline that turns scene data into pixels.

It was my graduation project for the CG Technical Director track at ITI, the capstone of a program where we learned each craft first and then how to build tools for it.

02What the engine covers

Lighting pipeline

A real-time lighting pipeline that shades the scene as it renders.

Shader system

Shaders written in GLSL, driven from C++, as the base for materials and lights.

Materials

Material definitions that describe how a surface responds to light.

Texture and UV mapping

UV mapping so textures land correctly on geometry.

GPU resources and memory

Direct control over GPU resources and memory, which is what Vulkan asks of you.

Qt interface

A basic Qt interface around the engine.

03My part

  • Built the shader system for materials, lights and texture / UV mapping, in GLSL and C++.
  • Wrote the basic Qt interface used to drive the engine.
  • Worked directly against Vulkan for GPU resource and memory control.

01Overview

SYNC turns speech audio into facial animation. A Python AI backend listens to the audio and produces blendshape weights, and those weights drive a 3D character's face so it lip-syncs in real time inside Autodesk Maya.

The point is to remove hand-keyed lip-sync: animators get a character that already talks along with the audio.

02Data flow

  1. Speech audioThe voice input the character should speak.
  2. AI backendA Python model turns the audio into facial motion.
  3. Blendshape weightsPer-shape values that describe the mouth and face pose.
  4. Maya characterThe weights drive the rig, so the lips sync in real time.

01Overview

When a game is localized into Arabic, the UI is where things break: text overflows, widgets clip, layouts flip, and a screen that worked in English can lead somewhere else entirely. Checking this by hand across every screen and every locale is slow and easy to get wrong.

SNOOP automates that check. It records real UI sessions in English, turns them into structured navigation paths, replays the same paths in Arabic, and certifies the state of each widget across locales. It is game-agnostic, so the same approach runs on both Unreal Engine 5 and Unity.

02How the pipeline works

  1. RecordA UI session is captured in English.
  2. StructureThe session becomes a structured navigation path.
  3. ReplayThe same path is replayed in Arabic.
  4. CertifyWidget states are certified across locales.

03Two engines, one core

Unreal Engine 5

Built as a UE5 C++ plugin and validated on Epic's Lyra Starter Game.

Unity

The core system was ported to Unity (C#) and validated on a shipped educational game, where a replay run certified 42 of 43 sessions with no foreign-screen navigation failures.
